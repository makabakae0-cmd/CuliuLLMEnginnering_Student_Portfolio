# Fungi 项目 15 周规划表（前后端协同版）

## 目标说明
本规划不是“课堂 demo”，而是可持续运行的全栈产品路线图。15 周结束后，系统应支持：
- 多设备访问（手机/平板/电脑浏览器可用）
- 用户账号体系（注册、登录、会话管理）
- 用户数据持久化（历史记录、偏好配置、课堂作业记录）
- 前后端联调上线（可部署到云端，非本地单机）

## 技术基线（建议）
- 前端：React/Vue + TypeScript + 响应式 UI
- 后端：Node.js (Nest/Express) 或 Python (FastAPI)
- 数据库：PostgreSQL（主库）+ Redis（缓存/会话）
- 部署：Docker + Nginx + 云服务器（或 Render/Railway/Fly.io）
- 监控：日志聚合 + 错误告警（Sentry/自建）

## 成品 MVP（第15周必须达成）
### 1) 用户与数据
- 支持注册/登录/退出。
- 用户信息、历史记录、任务提交可持久化。
- 同账号跨设备登录后数据一致。

### 2) 核心业务能力
- 输入真菌感染相关参数后，稳定输出结构化课堂解说。
- 输出具备科学准确性、非猎奇化表达、固定字段结构。
- 支持历史回看、课堂样本、任务提交。

### 3) 工程化能力
- 前后端独立部署，公网可访问。
- 至少一套自动化测试与基础监控告警。
- 有可维护文档：部署文档、接口文档、使用手册。

## 每周执行节奏（建议）
- 周一：本周需求冻结 + 任务拆分 + 风险评估。
- 周二到周四：开发与联调。
- 周五：周MVP验收（必须可演示）。
- 周末：复盘（进展、失败、下周修正）。

## 风险与预案
- 风险：AI输出不稳定。
  - 预案：模板约束 + few-shot + 结构化校验 + fallback文本。
- 风险：多设备样式问题反复。
  - 预案：建立断点规范与设备清单，固定回归脚本。
- 风险：后端性能瓶颈。
  - 预案：增加缓存、索引优化、分页与限流。
