# Fungi Simulator 测试与失败记录

本文档记录 Fungi Simulator 的主要正常测试和典型失败案例。它用于说明项目在课堂演示、科普体验和工程兜底方面做过哪些验证，以及遇到问题时如何保证 simulator 不完全中断。

用户产品介绍见 `README.md`，部署运行说明见 `TECHNICAL.md`，大模型工程判断见 `LLM_ENGINEERING_NOTES.md`。本文档是 `LLM_ENGINEERING_NOTES.md` 中“测试与失败分析”的依据。

## 测试范围

- 前端体验：页面展示、项目介绍、配置流程和游戏入口。
- AI 自动演示：AI vs AI 流程是否能从开始走到可解释结局。
- 感染模拟：触发感染后是否能进入阶段模拟并展示解说。
- RAG 问答：知识问答入口、示例问题和检索结果展示。
- 后端健康检查：`/api/health` 与 `/api/rag/health` 是否返回可读状态。
- 兜底能力：外部 API、RAG 或 AI 决策失败时，页面是否仍能继续演示。

## 正常测试记录

### 测试 1：首页与产品介绍

- 测试内容：打开项目首页，检查标题、项目定位、学习目标和主要功能是否能被用户快速理解。
- 预期结果：用户能看出这是一个真菌感染主题的科普学习 simulator，而不是开发者运行手册。
- 当前状态：通过。README 已改为面向用户的产品介绍，工程内容拆到 `TECHNICAL.md`。

### 测试 2：游戏配置与开始流程

- 测试内容：进入配置区，选择真菌、宿主和环境，启动游戏流程。
- 预期结果：页面能进入游戏地图，显示宿主、巢穴、孢子部署和行动控制相关区域。
- 当前状态：通过。该流程是课堂体验的主入口。

### 测试 3：AI vs AI 自动演示

- 测试内容：启动一键自动演示，观察真菌部署、宿主移动、感染或胜负结算是否连续发生。
- 预期结果：自动演示不应停在未完成状态，必须产生宿主胜利或真菌胜利等可解释结果。
- 当前状态：通过。已加入强制结算逻辑，避免“未触发胜负页面”的结尾。

### 测试 4：感染阶段模拟与 AI 解说

- 测试内容：让宿主触发感染，检查感染阶段、宿主状态和 AI 解说是否显示。
- 预期结果：感染过程按阶段推进，用户能读到当前阶段发生了什么。
- 当前状态：通过。外部 AI 不可用时，可使用本地解说兜底。

### 测试 5：RAG 知识问答

- 测试内容：在知识问答区输入或点击示例问题，检查是否能展示回答、检索片段和来源信息。
- 预期结果：RAG 可用时返回知识库结果；RAG 不可用时显示可读错误，不影响主模拟流程。
- 当前状态：通过主路径。RAG 仍依赖运行环境和 embedding 依赖，失败时走本地或可读错误兜底。

### 测试 6：后端健康检查

- 测试内容：访问后端健康接口和 RAG 健康接口。
- 预期结果：`/api/health` 能说明 Flask 后端可用；`/api/rag/health` 能说明知识库、collection 和依赖状态。
- 当前状态：通过。RAG 依赖缺失或数据库不可用时，接口返回诊断信息，而不是阻塞主服务。

## 失败案例记录

### 失败案例 1：GLM-5 API 返回 502 upstream_network_error

- 失败现象：调用 GLM-5 时出现 `502 upstream_network_error`，后端日志显示外部网络或代理无法连接 `open.bigmodel.cn`，例如 `Tunnel connection failed: 403 Forbidden`。
- 原因：本机或运行环境的代理、网络权限、外部服务状态不稳定，导致 `/api/generate` 无法拿到 GLM-5 响应。
- 启用的兜底方案：前端 AI 解说使用 `buildLocalAICommentary()` 本地生成局面分析；自动演示继续运行，不因外部 API 失败而中断。
- 修复方案 / 当前状态：后端仍保留 `/api/generate` 作为正式 AI 入口；当外部网络不通时，演示流程依靠本地 commentary fallback 保持可展示状态。

### 失败案例 2：自动演示结束出现“未触发胜负页面”

- 失败现象：AI vs AI 自动演示在感染结算等待超时后，没有进入明确的胜负页面，观众无法判断演示结果。
- 原因：原 auto-demo 流程只等待感染结算自然完成，超时后没有强制生成最终结果。
- 启用的兜底方案：加入 `forceAutoDemoResult()` 强制结算，保证自动演示一定进入宿主胜利或真菌胜利状态。
- 修复方案 / 当前状态：已修复。自动演示必须产生可解释结局，不再以“未触发胜负页面”作为结束状态。

### 失败案例 3：RAG 问答检索到错误材料

- 失败现象：用户提问生物知识时，RAG 或本地 fallback 检索到项目工程文档，例如版本表、工作簿或 Agent 维护材料，回答偏离真菌知识。
- 原因：ChromaDB 不可用时走本地关键词 fallback，但 fallback 来源曾包含 `Agent_completion_workbook.md`、项目说明等技术文档，导致生物问题被工程材料污染。
- 启用的兜底方案：保留本地关键词检索，但收紧默认 fallback 资料来源。
- 修复方案 / 当前状态：已移除技术文档作为默认 fallback 来源，只保留生物相关资料，并加入 death grip / 死亡紧咬等内置生物片段，减少知识问答跑偏。

## 当前遗留风险

- 截图和演示视频仍是占位，最终展示前需要替换成真实素材。
- GLM-5 依赖外部网络和 API 服务状态，网络受限时只能使用本地兜底。
- RAG 的 embedding 依赖较重，首次安装或环境受限时可能需要更多时间排查。
- 本地 fallback 能保证演示不断，但科学严谨性仍以 RAG 和人工校对后的资料为准。
