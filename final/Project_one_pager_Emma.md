## 1. 项目基本信息

- **项目名称**：Fungi Simulator
- **学生姓名 / 学号**：Emma / [您的学号]
- **目标用户**：生物学教师（用于课堂演示）、中学生/大学生（用于互动学习）
- **场景一句话**：在生物课堂或自主探究场景中，通过双人非对称对抗游戏模拟寄生真菌与昆虫宿主的博弈，利用本地大模型实时生成科学解说，解决传统科普枯燥、缺乏互动性的问题。

## 2. 问题定义

- **当前痛点**：
  1. **知识抽象难理解**：真菌感染宿主的微观过程（如菌丝生长、行为操控）难以通过静态图文直观呈现。
  2. **教学互动性差**：传统科普视频或课件是单向输出，学生缺乏参与感和策略思考。
  3. **个性化解说缺失**：现有教育软件无法根据玩家的具体操作（如选择了哪种蚂蚁、踩中哪个阶段的孢子）动态生成针对性的科学解释。

- **项目边界**：
  - 本项目**不包含**复杂的 3D 图形渲染引擎开发（使用简易 2D 网格或文字界面原型）。
  - 本项目**不涉及**多人在线联网对战，仅限本地双人同屏或人机对抗。
  - 本项目**不追求**完美的生物物理仿真，重点在于感染周期的逻辑正确性与解说的科学性。

- **成功标准**：
  1. 系统能完整运行“部署 - 规避 - 感染 - 解说”闭环流程。
  2. Ollama 模型能针对 8 个感染阶段生成准确且无幻觉的科学解说。
  3. 用户在测试中能清晰复述至少 3 个关于虫草真菌的关键知识点。

## 3. 最小可行方案（MVP）

- **输入是什么**：
  - 玩家选择配置（真菌种类、宿主种类、环境类型）。
  - 游戏状态事件（孢子放置坐标、宿主移动路径、是否触发感染、当前感染天数）。
- **输出是什么**：
  - 游戏胜负判定结果。
  - 基于当前游戏状态的实时文本解说（由 LLM 生成）。
  - 可视化的简易地图状态（文本或简单图形）。
- **核心流程**：
  1. **初始化**：玩家选择角色（如：偏侧蛇虫草 vs 木蚁），系统锁定地图规则。
  2. **博弈阶段**：真菌方隐藏部署孢子 -> 宿主方盲走规避（15 步）。
  3. **判定与模拟**：检测碰撞，若感染则进入"15 天周期模拟”。
  4. **AI 解说循环**：每过 1 天（游戏时间），调用 LLM 根据当前感染阶段生成一段科学解说，直至结局。

## 4. 技术方案草图

- **模型与环境**：`Ollama + qwen3.5:4b` (注：根据模板要求升级至 4b 版本以提升推理能力，本地部署)
- **Prompt 方案**：
  - 采用 `System Prompt` 设定专家人设（“你是一位精通昆虫病理学的生物学家”）。
  - 使用 `Few-Shot` 提供 8 个感染阶段的标准描述范例，约束输出格式（阶段名称 + 生理变化 + 行为特征）。
  - 动态注入上下文：将 `{current_day}`, `{fungus_type}`, `{host_type}`, `{symptoms}` 填入 Prompt。
- **RAG 方案**：后续阶段（M2 实施）。初期依赖模型内置知识，M2 阶段引入权威生物学论文片段作为知识库，确保解说严谨。
- **Agent / Tool 方案**：后续阶段。初期为线性流程，后期可让 Agent 自主判断是否需要查询外部数据库或调整难度。
- **安全与日志方案**：
  - **安全**：在 System Prompt 中严禁生成血腥、恐怖或鼓励自我伤害的描述，聚焦于自然生态循环。
  - **日志**：记录每局游戏的配置、关键转折点及 AI 生成的解说内容，用于后续评估准确性。

## 5. 数据与资料来源

- **数据来源列表**：
  1. **学术文献**：PubMed/Google Scholar 上关于 *Ophiocordyceps unilateralis* (偏侧蛇虫草) 和 *Cordyceps sinensis* (冬虫夏草) 的生命周期研究论文。
  2. **科普数据库**：National Geographic, BBC Earth 关于僵尸蚂蚁的纪录片字幕及图文资料。
- **数据质量风险**：
  - **时效性**：部分分类学名称可能更新（如真菌重新分类），需核对最新 taxonomy。
  - **偏差**：流行文化（如《最后生还者》）可能污染模型对真实生物习性的认知，需通过 RAG 纠正。

## 6. 评测计划（v1）

- **关键指标**：
  1. **科学准确性得分**：邀请生物老师对 AI 生成的 50 条解说进行打分（1-5 分），平均分需>4.0。
  2. **响应延迟**：从触发事件到生成解说的时间 < 3 秒（保证游戏流畅度）。
- **评测样本如何构建**：
  - 构造覆盖所有 8 个感染阶段、3 种真菌、4 种宿主的组合测试集（共约 30-50 个典型场景）。
- **失败样本如何记录**：
  - 建立 `error_log.json`，记录出现事实错误（如搞错宿主种类、描述错误的生理现象）的 Prompt 输入与输出，用于迭代 Prompt。

## 7. 里程碑计划（按 15 次课节奏）

- **M1（第 3 次课）**：完成游戏核心逻辑代码（Python），打通 Ollama 接口，实现基础 Prompt 生成解说，基线评测准确率 > 70%。
- **M2（第 7 次课）**：搭建 RAG 向量数据库，导入生物学文献，显著减少幻觉，解说专业性提升至专家水平。
- **M3（第 11 次课）**：引入简单的 Agent 机制，使 AI 能根据玩家水平动态调整解说深度；完善安全过滤机制。
- **M4（第 15 次课）**：整合 UI 界面，打包可执行文件，准备 Capstone 展示包（含演示视频、源代码、评测报告、用户手册）。

## 8. 风险与备选方案

- **主要风险**：
  1. **模型幻觉**：qwen3.5:4b 可能编造不存在的感染症状。
  2. **算力瓶颈**：本地运行模型导致游戏卡顿，影响体验。
  3. **规则复杂度过高**：双人对战规则难以用纯代码快速原型化。
- **对应备选方案**：
  1. 强制启用 RAG 检索增强，若检索置信度低则返回预设模板文本而非生成文本。
  2. 优化推理参数（如降低 max_tokens），或降级使用 qwen3:1.8b 配合更精细的 Prompt。
  3. 简化 MVP 版本为“单人剧情模式”，先验证 AI 解说核心功能，再扩展双人对抗。
