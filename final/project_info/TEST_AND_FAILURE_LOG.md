## 失败案例记录

### 失败案例 1：GLM-5 API 返回 502 upstream_network_error

- 失败现象：调用 GLM-5 时出现 `502 upstream_network_error`，后端日志显示外部网络或代理无法连接 `open.bigmodel.cn`，包括 `Tunnel connection failed: 403 Forbidden` 和 `NameResolutionError`。
- 原因：Python `requests` 自动读取系统代理设置时，请求经该代理建立 HTTPS tunnel 被 403 拒绝；受限运行环境还可能触发 DNS 解析失败。绕过环境代理并在正常网络中直连智谱接口可正常建立连接。
- 启用的兜底方案：真菌 AI 改用规则布阵，宿主 AI 改用本地回巢路线，AI 解说使用 `buildLocalAICommentary()`；自动演示不因外部 API 失败而中断。
- 修复方案 / 当前状态：已修复当前代理故障。后端改用独立 `requests.Session`，默认设置 `trust_env = false`；如确实需要环境代理，可设置 `GLM_TRUST_ENV_PROXY=1`。2026-07-24 实测 `/api/generate` 返回 HTTP 200 和 `OK`，`/api/rag/ask` 也能完成 GLM 综合回答；外部网络再次中断时继续依靠三类本地 fallback。

### 失败案例 2：自动演示结束出现“未触发胜负页面”

- 失败现象：AI vs AI 自动演示在感染结算等待超时后，没有进入明确的胜负页面，观众无法判断演示结果。
- 原因：原 auto-demo 流程只等待感染结算自然完成，超时后没有强制生成最终结果。
- 启用的兜底方案：加入 `forceAutoDemoResult()` 强制结算；超时兜底路径会生成真菌胜利结果，避免演示停在未完成状态。
- 修复方案 / 当前状态：已修复“没有结果页”的问题。正常流程仍可产生宿主或真菌胜利，只有超时强制路径固定以真菌胜利收束。

### 失败案例 3：RAG 问答检索到错误材料

- 失败现象：用户提问生物知识时，结果第 3、4 条出现 `ppt_pagesscript.md`，内容是“面向对象、目标时长、项目起点”等演示讲稿，与科学事实无关。
- 原因：演示讲稿和 `Lesson10_student_workbook.md` 同时进入了本地 fallback 来源；ChromaDB collection 中也可能保留这些文件的向量，因此只修改本地文件列表不足以彻底排除污染。
- 启用的兜底方案：保留内置 `death grip / 死亡紧咬`、行为操控等生物片段，确保过滤非科学来源后仍能返回可用证据。
- 修复方案 / 当前状态：已修复。移除非科学本地文件来源，并在 ChromaDB 查询结果层过滤 `ppt_pagesscript` 与 `lesson10_student_workbook`；查询时先获取最多 `top_k × 4` 个候选，过滤后再保留目标数量，避免坏资料占位导致证据不足。

### 失败案例 4：宿主 AI 持续走向地图左侧

- 失败现象：宿主没有持续接近巢穴，而是重复向左移动，甚至走到地图边缘。
- 原因：提示词只要求“优先”降低 `distanceToNest`，没有明确坐标方向；本地路线修复又只校验动作是否合法，没有拒绝让宿主远离巢穴的合法动作。原 fallback 的重复动作惩罚和无进展时选择次优候选也可能放大偏航。
- 启用的兜底方案：对 API 返回的每个 `move` / `burrow` 重新计算移动后距离；不严格接近巢穴的动作自动替换为本地最短方向。
- 修复方案 / 当前状态：已修复 API 返回路线的主要偏航问题。提示词明确 `right/left/down/up` 与坐标增减关系，并将“每次平面移动必须缩短欧式距离”设为硬目标；API 单步和多步计划会执行进展修复。本地 fallback 会按移动后距离优先选择候选，但尚未用独立测试证明所有边界状态都严格缩短距离。

### 失败案例 5：RAG 页面显示 `TypeError: Failed to fetch`

- 失败现象：结果页“知识库科学事实”显示 RAG 暂时不可用，浏览器无法完成对 `127.0.0.1:8002/api/rag/ask` 的请求。
- 原因：Flask 后端进程退出，8002 端口当时没有可用服务；该问题与 RAG 检索逻辑或宿主路线修改无关。
- 启用的兜底方案：结算页和知识问答先立即展示内置科学资料，在线 RAG 只做后台增强；网络异常不再向玩家显示底层错误字符串。
- 修复方案 / 当前状态：已在前端加入超时、失败冷却、本地科学资料和检索相关性门槛。8002 完全关闭时结算页仍可用；在线证据与当前真菌/宿主不相关时不会覆盖本地内容。2026-07-31 已分别完成后端开启与关闭的浏览器回归。

### 失败案例 6：窗口 resize 触发前端 TypeError

- 失败现象：控制台出现 `Cannot read properties of undefined (reading 'classList')` 和 `Cannot read properties of undefined (reading 'forEach')`，位置分别为 resize 回调中的 indicator 与 `gameState.foodItems`。
- 原因：窗口可能在 DOM 初始化完成前触发 resize，且初始 `gameState` 未声明 `foodItems`。
- 启用的兜底方案：resize 回调对 `hostIndicator`、`nestIndicator` 和 `foodItems` 做空值保护。
- 修复方案 / 当前状态：已修复。初始状态加入 `foodItems: []`，遍历改为 `(gameState.foodItems || []).forEach(...)`；`script.js` 语法和 lint 检查通过。

### 失败案例 7：RAG 文字颜色与浅色背景对比不足

- 失败现象：回答结论和证据正文受父级浅灰文字样式影响，在米白背景上过浅；首次加深后又出现正文颜色过于接近黑色、视觉层级单一的问题。
- 原因：`.notes-section p` 直接为段落设置浅色，优先于子容器继承色；后续仅统一加深正文，没有区分标题、重点和辅助信息。
- 启用的兜底方案：为 RAG 段落和列表直接指定颜色，避免依赖继承，并限定修改范围，不影响深色 notes 卡片的其他文字。
- 修复方案 / 当前状态：已调整为莫兰迪红色系变量，正文、主标题、小标题、强调句和辅助信息分别使用不同但足够深的颜色。静态 lint 通过，仍需浏览器视觉回归。

## 当前遗留风险

- 截图和演示视频仍是占位，最终展示前需要替换成真实素材。
- GLM-5 仍依赖外部网络和 API 服务状态；当前已绕过故障系统代理，但智谱服务不可用时仍需本地兜底。
- Flask 当前使用开发服务器；终端或父任务结束时需确认子进程仍在 8002 端口监听。正式部署应改用受进程管理器监管的 WSGI 服务。
- RAG 的 embedding 依赖较重，首次安装或环境受限时可能需要更多时间排查。
- 本地 fallback 已限定为内置生物片段，能保证演示不断，但覆盖面有限，科学严谨性仍以人工校对后的知识库资料为准。
- 莫兰迪红色文字方案已通过 CSS 静态检查，最终展示前仍需在实际屏幕和投影环境中确认对比度。
- `O. sinensis` 已配置 7 个感染阶段，但自动播放仍含旧的 8 段计时和结束判断；需要统一阶段推进逻辑并完成浏览器回归。
- V1 地图暂不包含不可移动障碍物，因此 Burrow 当前只校验边界、巢穴与冷却；加入障碍系统后需补充穿越判定。
- 目前没有浏览器端 E2E 或规则行为自动测试；静态检查与人工代码核对不能替代最终演示前的点击、动画和响应式布局回归。
